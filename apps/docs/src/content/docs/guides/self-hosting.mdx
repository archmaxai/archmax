## Deployment Modes

### Docker Compose (Recommended)

The recommended way to run archmax — separate containers for the app, MongoDB, and Redis:

```bash
git clone https://github.com/archmaxai/archmax.git
cd archmax
cp .env.example .env
# Edit .env with your values
docker compose up -d
```

The included `docker-compose.yml` runs archmax with dedicated MongoDB 7 and Redis 7 containers.

**Best for**: all deployments, from evaluation to production.

### Standalone Docker

If you manage MongoDB externally (e.g. MongoDB Atlas, a dedicated server), run archmax as a single container:

```bash
docker run -d \
  --name archmax \
  -p 8080:8080 \
  -e MONGODB_URI=mongodb://your-mongo-host:27017/archmax \
  -e BETTER_AUTH_SECRET=$(openssl rand -base64 32) \
  -e UI_PASSWORD=changeme \
  -v archmax-data:/app/data \
  archmax/archmax:latest
```

`MONGODB_URI` is required. Redis is embedded and starts automatically when `REDIS_URL` is not set.

**Best for**: users with existing MongoDB infrastructure or managed database services.

## Data Backup

archmax stores two categories of persistent data:

| Data | Location | Description |
|------|----------|-------------|
| Project files | `/app/data/projects/` (archmax container) | Semantic model YAML files |
| Database | MongoDB service/instance | Projects, connections, conversations, test data |

### Backing Up Project Files

<Steps>

1. **Stop the container** to ensure data consistency:

   ```bash
   docker compose stop archmax
   ```

2. **Copy the volume** to a backup location:

   ```bash
   docker run --rm \
     -v archmax_archmax-data:/data \
     -v $(pwd):/backup \
     alpine tar czf /backup/archmax-projects-$(date +%Y%m%d).tar.gz -C /data .
   ```

3. **Restart**:

   ```bash
   docker compose start archmax
   ```

</Steps>

### Backing Up MongoDB (Docker Compose)

```bash
docker compose stop
docker run --rm -v archmax_mongo-data:/data -v $(pwd):/backup \
  alpine tar czf /backup/archmax-mongo-$(date +%Y%m%d).tar.gz -C /data .
docker compose start
```

<Aside type="tip">
If you use a managed MongoDB service (Atlas, DocumentDB), rely on its built-in backup features instead.
</Aside>

### Restoring

```bash
docker compose stop
# Restore project files
docker run --rm \
  -v archmax_archmax-data:/data \
  -v $(pwd):/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/archmax-projects-20260408.tar.gz -C /data"
# Restore MongoDB
docker run --rm \
  -v archmax_mongo-data:/data \
  -v $(pwd):/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/archmax-mongo-20260408.tar.gz -C /data"
docker compose start
```

## Upgrading

<Steps>

1. **Pull the latest images**:

   ```bash
   docker compose pull
   ```

2. **Back up your data** (see above)

3. **Recreate the containers**:

   ```bash
   docker compose up -d
   ```

</Steps>

For standalone Docker:

```bash
docker pull archmax/archmax:latest
docker stop archmax && docker rm archmax
docker run -d --name archmax -p 8080:8080 \
  -e MONGODB_URI=mongodb://your-mongo-host:27017/archmax \
  -e BETTER_AUTH_SECRET=your-existing-secret \
  -e UI_PASSWORD=your-password \
  -v archmax-data:/app/data \
  archmax/archmax:latest
```

<Aside type="tip">
Keep your `BETTER_AUTH_SECRET` the same across upgrades — changing it invalidates all existing sessions.
</Aside>

## Resource Recommendations

| Deployment | RAM | Disk | CPU |
|-----------|-----|------|-----|
| Docker Compose (small) | 2 GB total | 5 GB | 1 vCPU |
| Docker Compose (production) | 4 GB total | 20 GB | 2 vCPU |
| Standalone (with external MongoDB) | 512 MB | 2 GB | 1 vCPU |

The AI agent's resource usage depends on your configured model provider (OpenRouter, OpenAI, etc.) — it runs as API calls, not locally.

## Security Considerations

- The embedded Redis binds to `127.0.0.1` only (container-internal) and is not exposed outside the container.
- Always set a strong `BETTER_AUTH_SECRET` (at least 32 characters).
- Change `UI_PASSWORD` from the default `changeme` before exposing to users.
- Place a reverse proxy (nginx, Caddy, Traefik) with TLS in front of port 8080 for HTTPS.
