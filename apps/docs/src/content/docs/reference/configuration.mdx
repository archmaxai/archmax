archmax is configured through environment variables. Set them in your shell, `.env` file, or Docker Compose config.

## Required Variables

| Variable | Description | Example |
|----------|-------------|---------|
| `BETTER_AUTH_SECRET` | Session encryption secret (min 32 chars). Save this value and reuse it across restarts. | Generate with `openssl rand -base64 32` |
| `UI_PASSWORD` | Initial admin password | `changeme` |

<Aside type="caution">
Save your `BETTER_AUTH_SECRET` somewhere safe. If you lose it or change it, all existing sessions and authentication data become invalid. You will need to re-authenticate after any change to this value.
</Aside>

## Database

| Variable | Default | Description |
|----------|---------|-------------|
| `MONGODB_URI` | _(embedded)_ | MongoDB connection string. **Optional in Docker**: when omitted, the container starts an embedded MongoDB instance at `/home/archmax/mongodb`. Set this to use an external MongoDB (e.g. `mongodb://localhost:27017/archmax`). |

## Server

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `3000` | API server port |
| `CORS_ORIGINS` | `http://localhost:5173` | Comma-separated allowed origins |
| `AUTH_BASE_URL` | `http://localhost:PORT` | Public URL for auth callbacks (set in production) |

## Admin Credentials

| Variable | Default | Description |
|----------|---------|-------------|
| `UI_USERNAME` | `admin` | Initial admin username (used to seed on first run) |
| `UI_PASSWORD` | - | Initial admin password |

Log in at `http://your-server:8080` with these credentials after deployment.

## Data Directory

| Variable | Default | Description |
|----------|---------|-------------|
| `ARCHMAX_DATA_DIR` | `/home/archmax/projects` (Docker) or `data/projects` (local) | Base directory for project data (YAML files) |

Inside the Docker image, the `archmax` user’s home is `/home/archmax/`; persistent application data lives there:

| Path | Contents | Persistent? |
|------|----------|-------------|
| `/home/archmax/projects/` | Semantic model YAML files | Yes |
| `/home/archmax/mongodb/` | Embedded MongoDB data (when using embedded mode) | Yes |
| `/home/archmax/.duckdb/` | DuckDB extension cache | Yes |
| `/tmp/redis/` | Embedded Redis data | No (ephemeral) |

A single bind mount (`-v ~/.archmax:/home/archmax`) maps that home directory to `~/.archmax` on the host, including project files, the DuckDB extension cache, and embedded MongoDB data. When using an external MongoDB via `MONGODB_URI`, the `mongodb/` directory is unused. See the [Docker Reference](/reference/docker/) for details.

## MCP Server

| Variable | Default | Description |
|----------|---------|-------------|
| `MCP_RATE_LIMIT_MAX` | `120` | Max requests per IP per 60-second window |

## AI Agent

<Aside type="caution">
`AGENT_API_KEY` is required for all AI-powered features: the Semantic Model Builder, Testing Playground, and automatic conversation title generation. Without it, these features will be unavailable and the chat interface will display a configuration warning.
</Aside>

| Variable | Default | Description |
|----------|---------|-------------|
| `AGENT_API_BASE_URL` | `https://openrouter.ai/api/v1` | OpenAI-compatible API endpoint. Change this when using a provider other than OpenRouter. |
| `AGENT_API_KEY` | - | **Required for agent features.** API key for your chosen provider. |
| `AGENT_MODEL` | `anthropic/claude-sonnet-4` | Model identifier (must match your provider's naming convention) |
| `AGENT_TITLE_MODEL` | - | Cheap/fast model for conversation title generation |

Supported providers: [OpenRouter](https://openrouter.ai) (default), OpenAI, Azure OpenAI, Ollama, or any OpenAI-compatible endpoint. To get started quickly, create an account at [openrouter.ai](https://openrouter.ai), generate an API key, and set `AGENT_API_KEY` to that value.

## Worker Queue

| Variable | Default | Description |
|----------|---------|-------------|
| `REDIS_URL` | _(embedded)_ | Redis connection URL for BullMQ worker queue. **Optional in Docker**: when omitted, the container starts an embedded Redis instance. Without Redis (local dev), the agent runs in-process. |
| `WORKER_CONCURRENCY` | `5` | Number of concurrent agent jobs per worker |

## Testing

| Variable | Default | Description |
|----------|---------|-------------|
| `TEST_AGENT_MAX_ITERATIONS` | `100` | Max tool call iterations for playground and batch test agents |
