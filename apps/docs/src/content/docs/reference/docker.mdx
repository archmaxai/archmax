## Image Contents

The `archsem/archsem` Docker image bundles everything needed to run archsem in a single container:

| Component | Description |
|-----------|-------------|
| **API server** | Hono HTTP server on port 3000 (internal) |
| **BullMQ worker** | Background job processor for AI agent tasks |
| **Frontend SPA** | React admin UI served as static files |
| **nginx** | Reverse proxy on port 8080 — routes `/api/` and `/mcp/` to the API, serves SPA for everything else |
| **MongoDB 7.0** | Embedded `mongod` — starts automatically when `MONGODB_URI` is not set |
| **Redis** | Embedded `redis-server` — starts automatically when `REDIS_URL` is not set |

Base image: `node:20-slim` (Debian Bookworm).

## Exposed Ports

| Port | Protocol | Description |
|------|----------|-------------|
| `8080` | HTTP | nginx reverse proxy — the only port you need to expose |

Internal services (API on 3000, MongoDB on 27017, Redis on 6379) bind to `127.0.0.1` and are not accessible from outside the container.

## Environment Variables

### Required

| Variable | Description |
|----------|-------------|
| `BETTER_AUTH_SECRET` | Session encryption secret. Min 32 characters. Generate with `openssl rand -base64 32`. Keep the same value across container restarts and upgrades. |
| `UI_PASSWORD` | Initial admin password. Used to seed the admin account on first run. |

### Database & Services

| Variable | Default | Docker Behavior |
|----------|---------|-----------------|
| `MONGODB_URI` | _(embedded)_ | **Optional.** When omitted, the entrypoint starts an embedded `mongod` at `mongodb://127.0.0.1:27017/archsem` with data at `/app/data/mongodb`. Set this to use an external MongoDB instance. |
| `REDIS_URL` | _(embedded)_ | **Optional.** When omitted, the entrypoint starts an embedded `redis-server` at `redis://127.0.0.1:6379` with ephemeral data at `/tmp/redis`. Set this to use an external Redis instance. |

### Server

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `3000` | Internal API server port. Normally not changed — nginx proxies port 8080 to this. |
| `CORS_ORIGINS` | `http://localhost:5173` | Comma-separated allowed origins. In Docker, the SPA is served by nginx on the same origin, so this is typically not needed. |
| `AUTH_BASE_URL` | `http://localhost:3000` | Public URL for auth callbacks. Set to your external URL in production (e.g. `https://archsem.example.com`). |

### Admin Credentials

| Variable | Default | Description |
|----------|---------|-------------|
| `UI_USERNAME` | `admin` | Initial admin username. |
| `UI_PASSWORD` | — | **Required.** Initial admin password. |

### Data

| Variable | Default | Description |
|----------|---------|-------------|
| `ARCHSEM_DATA_DIR` | `/app/data/projects` | Base directory for semantic model YAML files. Normally not changed in Docker. |

### AI Agent

| Variable | Default | Description |
|----------|---------|-------------|
| `AGENT_API_BASE_URL` | `https://openrouter.ai/api/v1` | OpenAI-compatible API endpoint. |
| `AGENT_API_KEY` | — | API key for the agent endpoint. Without this, the AI model builder and chat are disabled. |
| `AGENT_MODEL` | `anthropic/claude-sonnet-4` | Model identifier for the semantic model agent. |
| `AGENT_TITLE_MODEL` | `anthropic/claude-haiku-4-5-20250929` | Cheap/fast model for conversation title generation. |

### Worker

| Variable | Default | Description |
|----------|---------|-------------|
| `WORKER_CONCURRENCY` | `5` | Number of concurrent agent jobs the worker processes. |

### MCP Server

| Variable | Default | Description |
|----------|---------|-------------|
| `MCP_RATE_LIMIT_MAX` | `120` | Max MCP requests per IP per 60-second window. |

### Testing

| Variable | Default | Description |
|----------|---------|-------------|
| `TEST_AGENT_MAX_ITERATIONS` | `100` | Max tool call iterations for playground and batch test agents. |

### GitHub Integration (Optional)

| Variable | Default | Description |
|----------|---------|-------------|
| `GITHUB_CLIENT_ID` | — | GitHub OAuth app client ID. |
| `GITHUB_CLIENT_SECRET` | — | GitHub OAuth app client secret. |

## Volumes

| Container Path | Contents | Persistent? | Notes |
|---------------|----------|-------------|-------|
| `/app/data/projects/` | Semantic model YAML files | Yes | Core application data |
| `/app/data/mongodb/` | Embedded MongoDB data files | Yes | Only used when `MONGODB_URI` is not set |
| `/tmp/redis/` | Embedded Redis data | No | Ephemeral by design — queue data is transient |
| `/var/log/mongod.log` | Embedded MongoDB log | No | Useful for debugging startup issues |

### Recommended Volume Mount

```bash
-v archsem-data:/app/data
```

This single mount captures all persistent state (projects + embedded MongoDB). When using Docker Compose with external MongoDB, the project data mount is still needed:

```bash
-v archsem-data:/app/data  # Projects only (MongoDB is external)
```

## Entrypoint Behavior

The container entrypoint (`/entrypoint.sh`) follows this startup sequence:

```
1. Set ARCHSEM_DATA_DIR (default: /app/data/projects)
2. If MONGODB_URI is not set:
   ├── Create /app/data/mongodb (if missing)
   ├── Start mongod (bind 127.0.0.1, fork to background)
   ├── Wait for mongod to accept connections (up to 30s)
   └── Export MONGODB_URI=mongodb://127.0.0.1:27017/archsem
3. If REDIS_URL is not set:
   ├── Create /tmp/redis (if missing)
   ├── Start redis-server (daemonize, bind 127.0.0.1)
   └── Export REDIS_URL=redis://127.0.0.1:6379
4. Start BullMQ worker (background)
5. Start API server on port 3000 (background)
6. Start nginx on port 8080 (foreground — PID 1)
```

### Decision Matrix

| `MONGODB_URI` set? | `REDIS_URL` set? | Embedded MongoDB | Embedded Redis |
|:---:|:---:|:---:|:---:|
| No | No | Started | Started |
| Yes | No | Skipped | Started |
| No | Yes | Started | Skipped |
| Yes | Yes | Skipped | Skipped |

## Health Checks

The API exposes a health endpoint you can use for Docker health checks or load balancer probes:

```bash
curl -f http://localhost:8080/api/health
```

Docker `HEALTHCHECK` example:

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --start-period=30s \
  CMD curl -f http://localhost:8080/api/health || exit 1
```

Or in Docker Compose:

```yaml
services:
  archsem:
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/api/health"]
      interval: 30s
      timeout: 5s
      start_period: 30s
```

## Resource Requirements

| Deployment | Min RAM | Min Disk | Recommended CPU |
|-----------|---------|----------|-----------------|
| Single image (evaluation) | 512 MB | 1 GB | 1 vCPU |
| Single image (small team) | 1 GB | 5 GB | 1–2 vCPU |
| Docker Compose (production) | 2 GB total | 10 GB | 2 vCPU |

MongoDB is the primary memory consumer (~256 MB at idle). The AI agent runs remotely via API calls and does not consume local GPU/CPU.

## Examples

### Minimal (Zero Dependencies)

```bash
docker run -d \
  --name archsem \
  -p 8080:8080 \
  -e BETTER_AUTH_SECRET=$(openssl rand -base64 32) \
  -e UI_PASSWORD=changeme \
  -v archsem-data:/app/data \
  archsem/archsem:latest
```

### With External MongoDB

```bash
docker run -d \
  --name archsem \
  -p 8080:8080 \
  -e MONGODB_URI=mongodb://mongo.example.com:27017/archsem \
  -e BETTER_AUTH_SECRET=$(openssl rand -base64 32) \
  -e UI_PASSWORD=changeme \
  -v archsem-data:/app/data \
  archsem/archsem:latest
```

### With AI Agent Configured

```bash
docker run -d \
  --name archsem \
  -p 8080:8080 \
  -e BETTER_AUTH_SECRET=$(openssl rand -base64 32) \
  -e UI_PASSWORD=changeme \
  -e AGENT_API_KEY=sk-or-v1-your-key \
  -e AGENT_MODEL=anthropic/claude-sonnet-4 \
  -v archsem-data:/app/data \
  archsem/archsem:latest
```

### Docker Compose

See the [`docker-compose.yml`](https://github.com/archmaxai/archsem/blob/main/docker-compose.yml) in the repository root for a production-ready multi-service setup.

## Troubleshooting

### Container exits immediately

Check the logs for the startup error:

```bash
docker logs archsem
```

Common causes:
- Missing required environment variable (`BETTER_AUTH_SECRET` or `UI_PASSWORD`)
- `BETTER_AUTH_SECRET` is shorter than 32 characters

### Embedded MongoDB fails to start

The entrypoint waits up to 30 seconds for `mongod` to become ready. If it times out, the MongoDB log is printed to stdout. Check the logs:

```bash
docker logs archsem
```

Common causes:
- Corrupted data in the `/app/data/mongodb` volume (try with a fresh volume)
- Insufficient disk space
- Insufficient memory (MongoDB needs ~256 MB at minimum)

### Port 8080 already in use

Map to a different host port:

```bash
docker run -d -p 9090:8080 ... archsem/archsem:latest
```

### Volume permission errors

If running as a non-root user or on SELinux-enabled hosts, add the `:Z` flag:

```bash
-v archsem-data:/app/data:Z
```

### Cannot connect to external MongoDB

Verify the connection string from inside the container:

```bash
docker exec -it archsem mongosh "mongodb://your-host:27017/archsem" --eval "db.adminCommand('ping')"
```

Common causes:
- Network/firewall blocking the connection
- DNS resolution failure (use IP address or ensure Docker DNS resolves the hostname)
- Missing `?authSource=admin` for authenticated MongoDB instances
